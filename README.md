# CADI Assist

A conversational assistant for the [CADI website](https://cadi.port.ac.uk) at the University of Portsmouth. Staff ask a question in their own words and get a written answer drawn from CADI's own pages, with links to the pages it used.

**If you are setting this up for the first time, read [HANDOFF.md](HANDOFF.md) instead.** It is a step-by-step guide written for a Windows 11 machine and assumes nothing. This file is the reference.

---

## Everything in this document describes code that exists

The previous version of this project shipped a thorough README describing four features that were not in the codebase — a core-pages function, gap detection, conversation-aware scoring, and typo tolerance that did not tolerate typos. Anyone maintaining from that document was debugging behaviour that had never been written.

So: every claim below is checked by `node eval/run.mjs` and `node eval/smoke.mjs`, both of which run offline in under a second with no API key. If the documentation and the code ever disagree again, those two commands are the tiebreaker.

## 1. How it works

```
Staff member types a question
        |
index.html + app.js  (browser)
  - fetches search-index.json once, holds it in memory
  - ranks all 241 pages locally against the question
    plus the last 3 things the person said
  - sends the top 20 page extracts, and nothing else
        |
Cloudflare Worker  (worker/worker.js)
  - holds the API key
  - decides the model, the effort level and the system prompt
  - checks the origin, the rate limit and the daily cap
        |
Claude  (claude-sonnet-5)
  - answers from the supplied extracts, linking pages inline
        |
Browser renders the answer

Separately, every Sunday 02:00 UTC:
GitHub Actions -> scripts/crawl.py -> commits a fresh search-index.json
```

No server to run. The page is static files; the only moving server-side part is the Worker, which exists so the API key never reaches a browser.

**Ranking happens before the model is called.** The whole index is never sent. A typical request is roughly 4,000–6,000 input tokens regardless of how large the site grows.

## 3. Retrieval

### Scoring

Each page is scored against each meaningful word in the question. Stop words ("how", "do", "get", "the") are dropped first, because otherwise every page containing "get" competes with the pages that actually match.

| Field | Points per matching word |
|---|---|
| Title | 10 |
| Tags | 8 |
| URL slug | 6 |
| Tag phrase (multi-word tags) | 5 |
| Excerpt | 4 |
| Body, first 600 characters | 2 |
| Title precision (awarded once) | up to 8 |

**Title precision** is scaled by how much of the page's own title the question matched. Without it, "CPD and Support" ties with "Help Shape the Future of CPD at the University of Portsmouth" — both contain "CPD" — and the tie breaks arbitrarily. With it, the concise on-topic page wins.

**Tags currently contribute nothing.** Every page on cadi.port.ac.uk exposes an empty tag list, which is the Drupal tag-display issue recorded on TECH-519. The crawler looks for tags in meta keywords, taxonomy links and JSON-LD; if the issue is ever fixed they start counting automatically with no code change. Ranking does not depend on them.

### Typo tolerance

Matching is prefix containment first, then Damerau-Levenshtein edit distance — up to 1 edit for words of 5–9 characters, 2 for 10 or more.

Damerau rather than plain Levenshtein matters. Plain Levenshtein charges 2 edits for a transposition, which is the single most common typing error, so a budget wide enough to catch `timetbale` is also wide enough to match `optional` with `national`. Counting a swap as one edit keeps the budget tight. All of these resolve correctly, and all are real queries from the analytics export:

`timetbale` · `fellwoship` · `felowship` · `markeing` · `choises` · `curruculum` · `attendence` · `learnin` · `timetab;e`

### Glossary expansion

`config/glossary.json` maps a word the visitor uses to a different word the site uses — an acronym to its full name, or a synonym to the site's term. Acronyms and product names dominate real CADI searches, and plain keyword matching fails on all of them.

**The rule for adding entries:** only map to a *different* word, and never add generic words. Expanding `padlet` to "Padlet collaboration tool" let pages about collaborative growth outrank the actual Padlet page. Expanding `peer review` to "peer observation teaching" added "teaching", which appears in dozens of URL paths. Both expansions made search worse than none at all.

### Boosts

`config/boosts.json` promotes and demotes pages by URL pattern. A promotion only applies to a page that is *already* nearly winning: it must reach `boostFloor` (0.6) of the top relevance score, and the effect then grows as the square of how close it already was.

This is not decoration. An earlier design applied boosts as a flat multiplier and the boosted CPD page won "authentic assessment" because it mentioned "assessment design" in passing. The principle worth remembering:

> **Boosts break ties between relevant results. They never manufacture relevance.** If a page is not relevant, no weight should rescue it. If a page should be relevant but is not, the fix is a glossary entry or better page content, not a bigger number.

Demotions apply in full with no gate — suppressing low-value content needs no hedging. The current demotions exist because 45 staff biography pages and 60 conference session stubs were crowding out real guidance.

### Honest gaps

Two signals are computed and passed to the Worker, which turns them into explicit instructions in the system prompt:

- **`isGap`** — nothing cleared the minimum score. The model is told plainly that site search found nothing and must not attempt an answer.
- **`isWeak`** — something matched, but the best page matched fewer than half the question's terms in its title or URL. The model leads with the fact that it could not find a definite answer, then offers the closest page as a suggestion.

Pages whose only evidence is a fuzzy match somewhere in their body text are dropped entirely (`MIN_PAGE_SCORE`). That is almost always coincidence: it is how the query `gprof` reached a WISEflow page, because "Prof" is one edit away.

This is the part the previous version could not do. It padded results to 20 pages with zero-scoring content and left the model to notice, unaided, that nothing matched.

### Follow-up questions

Ranking uses the current message plus the last 3 user messages. "What about the timetable?" on its own retrieves nothing; after "Tell me about CPD" it retrieves CPD pages. `eval/smoke.mjs` asserts exactly that.

## 4. The Worker

`worker/worker.js` is in this repository. In the previous version it was not — the only copy lived in the Cloudflare dashboard.

It does four things:

1. **Holds the API key.** Nothing in the browser bundle is a credential.
2. **Owns the model, the effort level and the system prompt.** The browser sends only the conversation and the retrieved extracts.
3. **Checks the origin** against an allowlist and refuses anything else with a 403.
4. **Rate limits per IP and caps requests per day.**

Point 2 is the important change. The previous Worker forwarded the browser's body to Anthropic unchanged, so the caller chose the model, the token limit *and* the system prompt. That is not a search assistant; it is a free general-purpose Claude endpoint paid for by the University. `eval/smoke.mjs` includes a test that sends `model: claude-opus-5`, `max_tokens: 100000` and a replacement system prompt, and asserts all three are ignored.

### Endpoints

| Method and path | Purpose |
|---|---|
| `POST /api/ask` | Ask a question. Body: `{ messages, knowledge, isGap, isWeak }` |
| `GET /health` | Configuration check. Reports the model, whether the key is set, and **whether rate limiting is actually enforced** |
| `OPTIONS /api/ask` | CORS preflight |

`/health` reports its own misconfiguration on purpose. Rate limiting needs a KV namespace bound; without one the Worker still answers questions but there is no limit and no cap at all. That must not be able to go unnoticed, so it appears in `warnings`.

### Model settings

```js
model: 'claude-sonnet-5'
max_tokens: 2000
output_config: { effort: 'low' }
// temperature and top_p are deliberately NOT set
```

Three things to know, all of which are ways this can break:

- **A retired model ID returns an error with no fallback.** That is precisely what took the previous version off the air: it pinned `claude-sonnet-4-20250514`, which Anthropic retired on 15 June 2026. The crawler kept running weekly so the repository looked healthy while every message failed. Check [model deprecations](https://platform.claude.com/docs/en/about-claude/model-deprecations) once a term.
- **`temperature` and `top_p` must not be set.** Current Claude models reject non-default sampling parameters with a 400 error.
- **`max_tokens` covers thinking as well as the answer.** Current models think adaptively before replying, so a budget of 1,000 can be spent before the answer starts. 2,000 leaves room. `effort: 'low'` is Anthropic's documented recommendation for latency-sensitive chat.

## 5. Configuration

Two values in `app.js`, at the top of the file. Neither is a secret.

| Constant | What it is |
|---|---|
| `PROXY_URL` | Your Worker URL, including `/api/ask` |
| `INDEX_URL` | Raw GitHub URL of this repo's `search-index.json` |

Everything else lives in `worker/wrangler.toml` as environment variables, so changing the model, the limits or the wording is a config edit and a redeploy rather than a code change. See that file for the full annotated list.

## 6. The crawler

```bash
pip install requests beautifulsoup4 lxml
python scripts/crawl.py --url https://cadi.port.ac.uk
```

| Argument | Default | Purpose |
|---|---|---|
| `--url` | required | Root URL |
| `--max-pages` | `1500` | Page ceiling |
| `--stay-on-domain` | `true` | Only follow same-domain links |
| `--output` | `search-index.json` | Output file |
| `--min-pages` | `1` | Fail rather than write a suspiciously small index |

It reads `sitemap.xml` first, then follows links; respects `robots.txt`; waits 0.5s between requests; and prints a quality report showing thin pages, errors and tag coverage.

**What it excludes, and why it matters.** The previous crawler had no exclusions, so Drupal's tag-facet pages (`/search?keys=&field_tags_target_id[]=501` and 53 others) were indexed as content — 18% of the index, every one with the same 68 characters of text, all competing for space in the results. It also indexed `/cadi-news` and `/CADI-News` as separate pages, and tried to fetch a mailto address as a path. All three are fixed; the rules are unit-testable at the top of the file.

**If the Drupal theme changes**, content extraction is the thing that breaks. Update `CONTENT_SELECTORS` and `NOISE_SELECTORS`. The crawl workflow fails rather than committing if the page count drops below 70% of the previous run, so a broken selector shows up as a red build instead of an assistant that has quietly gone vague.

## 7. Testing

Both run offline. No API key, no network, no cost, under a second.

```bash
node eval/run.mjs              # retrieval quality: 38 real queries
node eval/run.mjs --verbose     # ...with the top 3 results for each
node eval/smoke.mjs             # end-to-end contract, API call stubbed
```

`eval/run.mjs` scores against `eval/baseline.json` and exits non-zero on a regression, which is how `eval.yml` blocks a merge that makes search worse. If a change is an intentional improvement, re-run with `--save-baseline` and commit the new figure.

The cases that assert *low confidence* matter more than the score suggests. `timetbale`, `peer review` and `enABLe` are among the most-searched terms on the site and none of them has a page. Those assertions record real content gaps and stop a later tuning pass from quietly replacing "I could not find that" with a confident wrong answer.

| `eval.yml` | Every push and pull request | Scans for committed API keys, validates the JSON, runs both test suites |

## 9. Costs

At CADI's observed volume — roughly 120 searches a month — running cost is pounds per year, not per month.

```
monthly cost ~= questions x (input tokens x input rate + output tokens x output rate)
```

A typical question is around 5,000 input tokens and a few hundred output tokens at `effort: low`. Check [current pricing](https://platform.claude.com/docs/en/about-claude/pricing) rather than trusting a figure written here; rates change.

The figure that actually matters is the worst case, not the average. Set a spend limit in the Anthropic console **and** keep `PER_DAY_TOTAL` set in the Worker. Together they make an abused endpoint a bounded problem.

## 10. Security and privacy

| Concern | How it is handled |
|---|---|
| API key | Cloudflare Worker secret only. Never in the repo, never in the browser. CI fails on a committed key-shaped string. |
| Endpoint abuse | Origin allowlist, per-IP per-minute and per-day limits, site-wide daily cap, request size caps. |
| Caller taking over the model | The Worker sets the model, token limit and system prompt. Client values are ignored. Tested in `eval/smoke.mjs`. |
| Prompt injection from page content | The system prompt states that knowledge-base content is material to read, never instructions to follow, and asks the model to flag pages that look unusual. There are no tools, so the worst case is a misleading answer, not an action. |
| Invented links | Not currently validated server-side. The prompt forbids constructing URLs and only supplies real ones — but a determined hallucination would still render. See [known gaps](#12-known-gaps-and-open-questions). |
| Cross-site scripting | Model output is rendered with `createElement` and `textContent`, never `innerHTML`. Links carry `rel="noopener noreferrer"`. |
| Personal data | Nothing is logged or stored. No conversation persists past a page refresh. Visitors see an "AI-generated answer, always check the linked page" notice. |
| Crawl politeness | `robots.txt` respected, identifiable user agent with a contact address, 0.5s delay, public pages only. |

**Not yet done:** a public AI answer service at the University may need information-governance or DPIA sign-off. That is an open decision on TECH-519, not something this code can settle.

## 11. Reusing this for another site

Nothing in `shared/scoring.mjs` is CADI-specific — core pages are found by URL pattern, not hardcoded ID. To stand it up for another department:

1. Copy the repository.
2. Run the crawler against the new site.
3. Replace `config/glossary.json` and `config/boosts.json` with that site's acronyms and priorities. Both can start empty.
4. Set `ALLOWED_ORIGINS`, `SITE_NAME`, `SITE_URL` and `CONTACT_EMAIL` in `wrangler.toml`, and deploy the Worker.
5. Update `PROXY_URL` and `INDEX_URL` in `app.js`.
6. Replace the cases in `eval/cases.json` with real queries from that site's analytics, and record a baseline.

Step 6 is the one people skip and the one that matters. Without it there is no way to tell whether a change helped.

## 12. Known gaps and open questions

Recorded honestly rather than left to be discovered.

**Content gaps found by building this.** Three of the most-searched terms on the site have no page at all:

| Searched for | Events | Status |
|---|---|---|
| `cpd timetable` / `timetable` | 16 combined | No timetable page exists. The assistant correctly says so. |
| `fellowship` and its variants | 7+ | No fellowship route page. Only news items mention it. |
| `peer review` / `observe well` | 3+ | No peer observation page. Collaborative Growth is the closest. |

These are content findings for CADI, not bugs. No amount of ranking work invents a page that does not exist.

**Also outstanding:**

- `SELL` and `gprof` appear in the analytics and nobody has been able to say what they stand for. Ask CADI, then add them to the glossary.
- Four glossary entries are marked `"confirm": true` — sector-standard expansions CADI has not verified.
- APEX, PrepUP, Docebo, Turnitin and SharePoint are searched for but have no CADI page. They need an `external-links.json` with confirmed destinations; a wrong link is worse than no link.
- `/teach-well` indexes with 43 characters of content, and two Teach Well pages return 403 to the crawler, so that content is missing from the index entirely.
- Citations are not validated server-side. The proper fix is to check every URL in the answer against the extracts that were sent and drop any that were not, which is a Worker change.
- The site calls itself "Centre for Academic and Digital Innovation". Some internal documents say "Academic Development & Innovation". Confirm which is right and use one form everywhere.
